About

A1
Nadia KerrData analyst · Leeds

I'm a data analyst who likes the unglamorous part first: finding out where a number really comes from. Most of my week is SQL and Python, cleaning and joining data so that a dashboard can be trusted by people who never see the query behind it.

I've worked in retail, housing and health-sector teams. I'm happiest when an analyst sits next to the people asking the questions, so the question gets sharper before any chart is drawn.

.How I

B2 — Four steps, same order, every time
01.B3

Ask

Start with the decision, not the dataset. Who needs to choose what, by when, and what would change their mind? I write that down before touching a table.

Workshop · brief
02.C3

Clean

Trace every field back to its source. Fix duplicates, gaps and odd dates in SQL and Python, and keep a plain-English log of every choice made.

SQL · Python
03.D3

Model

Build the smallest model that answers the question. Test it against numbers the team already trusts, and say clearly where it is weak.

Python · DAX
04.E3

Ex-
plain

Turn it into one page a busy person can read in two minutes. A dashboard if it will be used again, a short note if it won't.

Power BI · write-up

H8 — Principles

.Mani-
festo

Ask the dull questions first. Show the working. Say what you don't know.

H9.

Definitions first

If two people can read one number two ways, it isn't finished. Write the definition next to the chart.

H10.

Show the working

Every figure traces to a query someone else can run. If I can't explain it, I don't publish it.

H11.

Plain over clever

The simplest chart that answers the question wins. Decoration is a cost to the reader.
